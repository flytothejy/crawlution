# 밸런스 측정

종·기술을 바꾸거나 새 종을 넣을 때마다 같은 방법으로 다시 재서, 무엇이 얼마나 달라졌는지 본다.

```
npm run balance:quick          # 빠른 점검(2코어 약 4분) — 기술을 고친 직후
npm run balance                # 전체 측정(2코어 약 20분) — 조정을 마무리할 때
npm run balance -- --baseline  # 보고서는 지난 기준선과 비교해 만들고, 이번 결과를 새 기준선으로 저장
npm run balance -- --only=bench        # 한 층만(bench·duel·arena, 쉼표로 여럿). 나머지 층은 지난 결과를 쓴다
npm run balance -- --only=none         # 측정 없이 보고서만 다시 만든다(가중치를 바꿨을 때)
```

결과: `balance/out/report.html`(보기용 — 게시된 '크롤루션 밸런스 보고서' 아티팩트 `68222dcd-0f35-4fcc-91f3-67eea1c75132`에 다시 올린다), `balance/out/analysis.json`, `docs/balance.md`(저장소 기록).
`balance/baseline.json`(분석 결과만, 약 170KB)은 저장소에 넣어 둔다 — 조정 전후를 비교하는 기준. 원자료(`balance/out/latest.json`)는 넣지 않는다.

## 네 층

| 층 | 파일 | 무엇을 | 봇 AI |
|---|---|---|---|
| 기술 실측 | `bench.ts` | 종마다 4칸 기술을 고정 장면에서 한 번 써서 피해·제어·지킨 체력·이동을 잰다 | 안 낌 |
| 1:1 대전표 | `duel.ts` | 40종 모든 쌍을 같은 레벨로 붙인다(시드 × 자리 바꿈) | 낌 |
| 아레나 판 | `arena.ts` | 21마리 5분 판. 종별 K/D·순위·생존, 기술 칸별 실전 사용·피해, 붙잡힌 교전의 생존율·쓰러지기까지 시간 | 낌 |
| 탈출 실험 | `escape.ts` | 체력 35%로 쫓길 때 방어 기술이 준비된 경우와 대기 중인 경우의 생존율 차이 | 낌 |

기술 실측은 봇 실력과 상관없는 '숫자 그대로의 세기'다. 1:1·아레나는 실제 판에서의 결과지만 봇 AI가 기술을 얼마나 잘 쓰는지가 섞인다.
셋을 같이 보면 원인이 갈린다:
- 실측도 세고 실전도 셈 → 수치를 낮춘다.
- 실측은 보통인데 실전이 셈 → 기술끼리의 조합·계열 특성·본능을 본다.
- 실측은 센데 실전이 약함 → 봇이 그 기술을 잘 못 쓴다(봇 판단을 고치거나 사람 손에서 다시 본다).

### 기술 실측 장면

- **공격 장면**: 앞쪽에 허수아비 3마리(무당거미, 같은 레벨, 제자리 맴돌기, 쓰러지지 않음). 기술 칸에서 나온 피해(장판·투사체·소환수·독까지), 걸린 상태 시간, 밀어낸 거리, 회복, 내가 숨거나 무적이던 시간.
- **방어 장면**: 세 방향에서 0.5초마다 한 방향당 최대 체력 4%(3초에 72%). 안 쓴 판보다 지킨 체력(막기·무적·피해 감소·회복).
- **이동 장면**: 혼자 직진. 쓰고 1.5초 동안 더 간 거리.
- 레벨 6(각성 전)·12(각성 후), 시드 2개 평균.

### 기술 가치

실측 값을 '상대 최대 체력 비율' 한 단위로 바꾼다(`weights.ts`). 1:1에서 서로 초당 약 20%를 깎으므로 1초 기절 ≈ 0.2.
공격·방어·특수는 10초당 가치(가치 ÷ 쿨 × 10), 필살기는 한 번당 가치. 같은 칸 중간값으로 나눈 '칸 대비'가 1이면 보통.

### 기술 칸 표시(src)

시뮬레이션이 피해마다 어느 기술 칸(atk·def·spc·ult)에서 나왔는지 `hit` 이벤트에 `src`로 붙인다.
기술을 쓸 때 정해져서 나중 일(later)·예고 공격·장판·투사체·소환수·독·가려움으로 이어진다. 물기와 특성·본능 피해는 `src`가 없다(보고서의 bite·etc).

### 표시 기준(`weights.ts`의 FLAG)

- 기술: 칸 대비 1.6배 넘음 / 0.55배 밑, 실측에서 안 나감, 실전 사용이 칸 중간값의 30% 밑(봇이 거의 안 씀), 한 칸이 실전 피해의 60% 넘음
- 종: 1:1 승률 60% 넘음 / 40% 밑, 강함 지수(1:1 승률·판 순위·K/D 표준점수 평균) ±1.4 넘음

## 새 종·기술을 넣으면

1. `src/shared/v3.ts`에 종을 넣고 `kit.ts`·`skills3.ts`로 기술을 잇는다(테스트 `npm test`가 기술이 나가고 맞는지 본다).
2. `npm run balance:quick` → 보고서의 '살펴볼 것'에서 새 종·기술 확인.
3. 수치를 고치고 2를 되풀이. 마무리는 `npm run balance`, 괜찮으면 `--baseline`.

## 실유저 층(사람이 둔 판)

1. 판이 끝나면 게임이 판 기록(`ReplayRecord`)을 만든다(`src/client/host.ts`의 `lastReplay`, 브라우저에서는 `window.__lastReplay`). 출시 뒤에는 순위 서버가 모은다.
2. 기록 JSON(하나 또는 배열)을 `balance/replays/inbox/`에 넣고 `npm run balance:ingest`.
   - 같은 버전 도장(`SIM_BUILD`)의 기록만 다시 돌린다. 다른 도장이면 `git checkout sim-<도장>` 뒤 다시 돌리거나 `-- --allow-other-build`(근사, 결과가 어긋날 수 있음).
   - 다시 돌려 뽑은 지표를 `balance/replays/runs/<id>.json`에 남기고, 처리한 기록은 `inbox/done/`으로 옮긴다. 지표는 코드가 바뀐 뒤에도 그대로 쓴다.
3. `npm run balance -- --only=none` → 보고서 '실유저' 탭: 사람 K/D·붙잡힌 뒤 생존·쓰러지기까지·방어 기술 사용·판 순위를 같은 판 봇과, 종별로는 봇끼리 아레나의 같은 종과 나란히.

결정성은 `test/determinism.test.ts`가 지킨다(기록 → 다시 돌리기 → 같은 판, 공유 코드의 `Math.sin`·`Math.random` 등 직접 사용 금지, 버전 도장 최신).
