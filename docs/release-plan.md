# 출시 대비 점검

목적: 게임 완성이 먼저다. 다만 지금 안 해 두면 나중에 고치기 비싸지는 것을 미리 골라 둔다.
(2026-11-26 기준 코드 상태로 점검)

## 출시 목표와 현실성

| 단계 | 목표 | 판단 |
|---|---|---|
| 1 | 크레이지게임스: 1인 아레나 + 기록 누적·전체 순위 | 현실적. **전체 순위는 처음부터 자체 서버**로(아래 '전체 순위 설계'). 크레이지게임스 순위표(초대제)는 쓰지 않는다 |
| 2 | 자체 웹: 멀티 아레나 | **수정 권장.** 기술은 가능(시뮬레이션이 서버로 옮기기 좋은 구조)하지만 자체 웹엔 사람이 안 온다 → 빈 방. 멀티 서버는 우리 것으로 두고 **입구는 크레이지게임스 + 자체 웹 둘 다**(크레이지게임스는 멀티 게임도 받고 친구 초대 기능이 있다). 사람이 적으면 빈자리를 봇으로 채운다 |
| 3 | 앱 또는 스팀: 모험 모드로 확장 | 장기 목표로 적절. **둘 중 하나만** — 크레이지게임스에서 모바일 비율·재방문을 보고 고른다. 스팀은 그림·분량 기대가 높아 앱이 먼저일 가능성이 크다 |

## 전체 순위 설계(처음부터 자체 서버)

### 사용자 구분

| 어디서 | 누구로 | 순위 등록 |
|---|---|---|
| 크레이지게임스(로그인) | SDK `getUserToken()`의 JWT를 서버가 크레이지게임스 공개키로 검증 → `cg:<userId>`, 이름은 크레이지게임스 이름 | 됨 |
| 크레이지게임스(손님) | 검증할 신원이 없음 | 순위는 보기만, 등록하려면 '크레이지게임스 로그인' 버튼(자동으로 띄우지 않음) |
| 자체 웹·앱 | 서버가 발급한 기기 계정(id + 비밀 토큰) + 별명(금칙어 거름). 나중에 구글 등 로그인·계정 잇기 | 됨 |

크레이지게임스 판에는 다른 로그인을 넣지 않는다(크레이지게임스 조건). 플랫폼별 순위를 따로 둘지 합칠지는 서버에서 정한다(기본: 합친 전체 + 플랫폼 표시).

### 무엇을 겨루나(재미)

- **주간 시즌 순위**(월요일 초기화): 이번 주 한 판 최고 점수. 밸런스 패치는 시즌 경계에 맞춘다.
- **명예의 전당**: 역대 최고 점수.
- **종·계열별 순위**: "이번 주 왕사마귀 1위" — 40종이라 누구나 어딘가에서 상위권을 노릴 수 있다.
- **나라별·내 주변 순위**(내 위아래 5명), 결과 화면에 "이번 주 312위 → 87위".
- 조건이 같은 판만 등록: 표준 아레나(봇 20, 같은 게임 버전, 아들 모드 같은 배율 없음).

### 점수 조작 막기(판이 내 브라우저에서 돌아가므로 핵심)

1. **서버가 판을 연다**: 시작 때 서버가 시드·판 id를 준다. 결과는 그 판 id로만, 판 시간(5분)이 지난 뒤에만 받는다. 오프라인 판은 순위 밖.
2. **그럴듯함 검사**: 분당 점수 상한, 버전, 시간, 너무 잦은 제출 거르기.
3. **판 다시 돌려 확인(재생 검증)**: 시뮬레이션이 결정적이라 '시드 + 입력 기록'만 있으면 서버가 같은 판을 다시 돌려 점수를 직접 계산할 수 있다. 한 판 다시 돌리기에 CPU 약 25초라 **순위 상위에 들어갈 기록만** 검증한다(대부분의 제출은 검증할 필요가 없다). 검증 전 기록은 '확인 중' 표시.

### 지금 정해야 하는 두 가지(늦으면 비쌈)

- **입력 기록**: 판 안에서 `Command`가 바뀔 때 틱 번호와 함께 기록한다(시뮬레이션 쪽에서). 방향은 시뮬레이션에 넣기 전에 일정 단위로 잘라 기록과 실제가 같게 한다. 5분 판 기준 수십 KB.
- **브라우저마다 같은 계산**: 자바스크립트의 `Math.sin·cos·atan2·hypot`은 브라우저 엔진마다 마지막 자리가 다를 수 있다(규격상 근사 허용) → 아이폰 사파리에서 한 판을 서버(Node)가 다시 돌리면 어긋날 수 있다. 공유 코드에 이 함수들이 약 230곳. **결정적 수학 함수(`shared/dmath.ts`)로 지금 바꿔 두면** 기계적 작업이지만, 코드가 더 늘어난 뒤엔 비싸진다. 테스트로 `Math.sin` 등 직접 사용을 막는다.

### 서버

- **Node(TypeScript) 서버 하나 + Postgres**: 시뮬레이션 코드(`src/shared`)를 그대로 써서 재생 검증을 하고, 나중에 **같은 서버가 멀티 방도 맡는다**(목표 2와 이어짐). 작은 서버 하나로 시작.
- 엣지 함수형(서버리스)은 순위 저장엔 충분하지만 한 판 25초 재생 검증엔 실행 시간 제한이 걸린다.
- 저장: 사용자, 판 기록(시드·버전·종·점수·순위·처치/쓰러짐·검증 상태·입력 기록), 시즌별 최고 기록.

## 지금 해 둘 것

### 구조(늦게 고치면 전부를 건드림)

1. **문자열 분리(다국어 준비)** — 한글 문장이 코드·데이터에 약 1,000줄(`species.ts` 245, `renderer.ts` 275, `v3.ts` 173, `main.ts` 121, `cards.ts` 117 …). 종·기술이 늘수록 비용이 커진다. 지금 키 기반 사전(ko 먼저, en 자리만)으로 옮기고, 번역은 출시 직전에.
2. **플랫폼 연결부 한 곳으로** — 저장(`localStorage` 직접 13곳), 사용자, 광고, 판 시작·끝 신호, 공유를 `platform` 인터페이스 하나로. 지금은 웹 구현만 두고, 크레이지게임스·앱 구현은 나중에 끼운다. 크레이지게임스는 진행 저장을 데이터 모듈로 하라고 하므로 직접 저장이 흩어져 있으면 다 고쳐야 한다.
3. **저장 데이터 설계** — 버전이 붙은 프로필 하나(설정·마지막 곤충·누적 기록·해금), 1MB 미만, 버전 올릴 때 옮기는 함수. 판 결과 요약 형식(시드·게임 버전·종·점수·순위·처치/쓰러짐·기술 사용)을 지금 정한다 → 내 기록·전체 순위·밸런스 분석이 같은 형식을 쓴다.
3-1. **입력 기록 + 결정적 수학 함수** — 위 '전체 순위 설계' 참고. 재생 검증의 전제.
4. **멀티 대비 시뮬레이션 정리**
   - (a) 타격 멈춤(`freezeT`)이 판 전체를 멈춘다 → 화면 연출로 옮긴다(멀티에선 남의 타격에 내 판이 멈추면 안 됨).
   - (b) 플레이어 전용 분기 14곳(`isPlayer`: 아들 모드 피해 배율, 부활 지연, 연출 이벤트 …) → '사람이 조종' 속성으로 바꾸고 판 규칙은 사람·봇 같게.
   - (c) 스냅샷이 매 틱 판 전체 → 네트워크용 '시야 안 + 바뀐 것만'은 멀티 착수 때. 지금은 화면이 스냅샷만 보고 그리는 구조를 지킨다.
   - (d) `Math.random` 금지(이미 정리됨) — 시드만 같으면 판이 똑같이 재현되는 성질을 테스트로 지킨다.
5. **모드 경계 확정** — 아레나는 공평(판 밖 성장이 전투력에 영향 없음: 해금·꾸미기·칭호만), 모험은 누적 성장. 저장 구조와 밸런스 측정이 이 경계를 전제로 한다.

### 콘텐츠·제작

6. **정식 이름 조기 확정** — 크레이지게임스 페이지 주소, 도메인, 앱 ID, 상표, 저장 키(`crawlution.*`)가 모두 이름에 묶인다.
7. **바로 시작 흐름** — 첫 진입은 한 번 클릭으로 판 시작(기본 또는 지난번 곤충). 고르기는 메뉴에서. 모험도 첫 진입은 1스테이지로 바로.
8. **봇 표시 원칙** — 봇을 사람처럼 보이게 하지 않는다(이름 옆 표시 등). 멀티에서 사람과 섞일 때도 같은 원칙.
9. **그림·소리** — 지금은 코드로 그린 그림. 앱·스팀까지 가면 그림을 바꿀 수 있게 '모양 데이터(look)' 중심 구조를 유지한다. 배경음악 추가.
10. **성능 기준** — 저사양 휴대폰에서 목표 프레임과 재는 방법을 정한다(크레이지게임스는 기기 폭이 넓다).

### 데이터·운영

11. **사람 판 기록 수집** — 판 결과 요약을 익명으로 모아 밸런스 측정 체계에 '사람 층'을 더한다. 출시 전엔 형식만.
12. **판 재현** — 시드 + 입력 기록으로 판을 다시 돌린다 → 순위 검증(전체 순위 설계)·버그 재현.
13. **게임 버전 표기** — 기록·순위·밸런스 결과에 버전을 붙인다.

### 보호·법

14. 저장소 비공개(현재 공개). 사이트 잠금·난독화는 플랫폼별 빌드 옵션으로.
15. 국내 자체 웹·앱은 등급분류(앱은 스토어 자체 등급), 표현 수위는 PEGI 12, 자체 웹 로그인을 하면 개인정보 처리방침.

## 지금 안 해도 되는 것

광고 SDK, 결제, 멀티 서버, 번역 작업 자체, 앱 포장, 스팀 페이지.
